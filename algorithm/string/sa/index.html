后缀数组

2026-08-07

流程

最普通的 SA 需要两个数组：sasasa 和 rkrkrk。
其中 sa[i]sa[i]sa[i] 表示所有后缀中，字典序排名为 iii 的后缀的起始字符串下标。
rk[i]rk[i]rk[i] 表示起始下标为 iii 的后缀的字典序排名。

容易发现，这两个数组的定义是相反的，也就是说：sa[rk[i]]=i,  rk[sa[i]]=isa[rk[i]]=i,\; rk[sa[i]]=isa[rk[i]]=i,rk[sa[i]]=i。

接下来的问题变成了如何求 sasasa 和 rkrkrk，一个比较直白的想法是直接枚举所有后缀然后排序，可是时间复杂度 O(n2log⁡n)O(n^2\log n)O(n2logn)，考虑如何优化。
我们每次都是一个一个比较，有没有什么办法一次比较多个呢？有的有的，倍增了解一下：

  • 对于第一次排序，我们以每个后缀的第一个字母（这不就是原序列）为第一关键字进行排序，得到第一次的 sa1,rk1sa_1,rk_1sa1​,rk1​。
  • 第二次排序，我们将每个后缀的 rk1[i]rk_1[i]rk1​[i] 作为第一关键字，第一个字母向后 20=12^0=120=1 个字母为第二关键字排序，得到 sa2,rk2sa_2,rk_2sa2​,rk2​。

以此类推，每次都以上一次的 rkirk_irki​ 作为第一关键字，然后将向后偏移 2i2^i2i 作为第二关键字，排序后求出新的 sai+1,rki+1sa_{i+1},rk_{i+1}sai+1​,rki+1​。
特别的，如果一个字符向后的位置没有字符，将其第二关键字视为 000（其实可以直接塞到排序完的序列里）。

这么做是 O(nlog⁡2n)O(n\log^2 n)O(nlog2n) 的，还可以继续优化到 O(nlog⁡n)O(n\log n)O(nlogn)，即利用基数排序，这样能将排序做到 O(n)O(n)O(n)，总复杂度即为 O(nlog⁡n)O(n\log n)O(nlogn)。

首先是预处理，我们将所有 s[i]s[i]s[i] 作为第 iii 个后缀的第一关键字进行排序：

for(int i = 1 ; i <= n ; i ++) c[x[i] = s[i]] ++;
for(int i = 2 ; i <= m ; i ++) c[i] += c[i-1];
for(int i = n ; i >= 1 ; i --) sa[c[x[i]] --] = i;

注意，这里 c[i]c[i]c[i] 表示不大于 ASCII 码为 iii 的后缀有多少个，最终后续填充 sasasa 保证了稳定性（关键字相同时，相对顺序不变）。

然后，我们开始倍增循环：

for(int k = 1 ; k <= n ; k <<= 1) {
    int num = 0;
    for(int i = n-k+1 ; i <= n ; i ++) y[++ num] = i;
    for(int i = 1 ; i <= n ; i ++)

    if(num == n) break;
    m = num;
}

第二段中，清空 ccc 并统计第一关键字 xxx 的出现次数，按照 yyy 的逆序遍历放入 sasasa 中（yyy 的逆序保证了第二关键字大的在右边），然后清空 yyy。

第三段中，交换 x,yx,yx,y，此时 yyy 中存储的是长度为 kkk 的排名，我们要将 xxx 重新赋值为 2k2k2k 的排名，注意，这里 y[sa[i]] == y[sa[i-1]] && y[sa[i]+k] == y[sa[i-1]+k] 最多越界到 n+1n+1n+1，所以并不需要开大数组（因为 && 的短路性质）。
